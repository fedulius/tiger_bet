# CLAUDE.md

Этот файл задаёт общие правила работы для Claude Code в проекте. Следуй им по умолчанию, если пользователь явно не попросил иначе.

## Общие принципы
- Делай только запрошенные изменения.
- Не трогай несвязанные файлы и участки кода без необходимости.
- Предпочитай минимально инвазивные правки вместо широкого рефакторинга.
- Сначала изучи текущую реализацию, потом меняй код.
- Сохраняй существующий стиль кода, соглашения по именованию и структуру проекта.
- Не добавляй новые зависимости без явной необходимости.
- Не оставляй временные заглушки, TODO, фейковые данные и мёртвый код.
- Не меняй env/config/secrets/infrastructure, если задача не про это.

## Работа с кодом
- Проверяй, какие файлы уже изменены, до внесения собственных правок.
- Не перезаписывай и не ломай чужие незавершённые изменения.
- Если меняется API-контракт, проверь связанные места использования.
- Если есть несколько вариантов решения, выбирай самый простой и поддерживаемый.
- Не делай commit, push, force-push, merge или rewrite history без явного запроса.

## Проверка результата
- Перед завершением обязательно проверь результат реальным запуском релевантных команд.
- Запускай только те проверки, которые относятся к изменению: точечные тесты, сборка, линтер, локальный сценарий.
- Не заявляй, что задача выполнена, пока не выполнена проверка или пока явно не описан блокер.
- Если проверка не запускается из-за окружения или внешних ограничений, честно укажи это.

## Формат отчёта по результату
В финальном сообщении кратко укажи:
- что изменено;
- какие файлы затронуты;
- что именно проверено и какой результат;
- какие есть риски, ограничения или что не удалось проверить.

## Правила для tiger_bet
- Корень проекта: `/home/fedulov/tiger_bet`.
- Согласовывай шаги, если задача затрагивает несколько частей системы или имеет заметные побочные эффекты.
- Перед `pm2 restart 0` обязательно делать build фронтенда, если менялся фронтенд.
- Использовать короткие роуты; не вводить `/api/webapp/*` alias.
- Миграции: только целевой сервис.
- Для webapp-сервиса проверять доступ по `user_id` в пуле оплативших.
- Авторизация должна идти через отдельного Telegram-бота.
- Время матчей в webapp показывать в формате `YYYY-MM-DD HH:mm` в московском времени (UTC+3).
- Для прогнозов использовать основной прогноз / выбор редакции, без принудительного П1/П2/Х.

## Предпочтительный порядок работы
1. Быстро понять задачу и затронутые части системы.
2. Посмотреть текущую реализацию и связанные файлы.
3. Внести минимальные необходимые изменения.
4. Выполнить релевантную проверку.
5. Коротко отчитаться по шаблону выше.
